ROUTES API À CRÉER (préfixe : /api/ecc) :
  POST /api/ecc/generate-key     → Générer paire de clés (privée k, publique Q=k·G)
  POST /api/ecc/encrypt-file     → Chiffrer fichier avec clé publique
  POST /api/ecc/decrypt-file     → Déchiffrer fichier avec clé privée

CONSEILS D'IMPLÉMENTATION :
  1. Utilisez la bibliothèque Python "tinyec" ou implémentez manuellement
     les opérations : addition de points, multiplication scalaire
  2. Paramètres de courbe recommandés pour l'éducation :
     Courbe : secp256k1 ou courbe custom avec petits paramètres
  3. Pour le chiffrement de fichier, utilisez ECIES :
     - Choisir k aléatoire
     - C1 = k·G  (point éphémère)
     - Secret partagé = k·Q (clé publique destinataire)
     - Dériver clé symétrique AES via SHA256(secret)
     - Chiffrer le fichier avec AES
  4. Côté frontend, réutilisez le style de RSAPage.module.css

STYLE UI À RESPECTER :
  - Couleur accent : #00c896 (vert)
  - Même structure que RSAPage (section, dropzone, keyBox, alert)
  - Variables CSS globales dans src/index.css

INSTALLATION DÉPENDANCE (si tinyec) :
  pip install tinyec
  Ajoutez "tinyec" dans backend/requirements.txt

ROUTES API À CRÉER (préfixe : /api/rsa-attack) :
  POST /api/rsa-attack/factorize    → Factoriser n pour trouver p et q
  POST /api/rsa-attack/wiener       → Attaque de Wiener (d petit)
  POST /api/rsa-attack/brute-force  → Force brute petit exposant

ATTAQUES RSA À DÉMONTRER :

  1. FACTORISATION DE n (force brute)
     Entrée  : n (petit pour démo)
     Sortie  : p, q trouvés + d calculé + étapes
     Algo    : Tester diviseurs jusqu'à √n

  2. ATTAQUE DE WIENER
     Contexte : Quand d est trop petit (d < n^0.25)
     Entrée   : e, n
     Sortie   : d trouvé via fractions continues
     Algo     : Développement en fractions continues de e/n

  3. ATTAQUE PETIT e (e=3, Håstad)
     Contexte : Même message chiffré avec e=3 pour 3 clés
     Entrée   : 3 chiffrés, 3 modules
     Sortie   : message original via théorème CRT

STYLE UI :
  - Couleur accent : #ff6b35 (orange)
  - Affichez les étapes mathématiques de l'attaque
  - Indicateur de progression / étapes visitées
  - Message pédagogique expliquant la vulnérabilité

CONSEIL :
  Séparez la logique backend (algorithme pur) du frontend (affichage).
  Le backend retourne JSON avec : { success, steps: [...], result: {...} }

ROUTE FRONTEND ASSIGNÉE : /ecc-attack

ROUTES API À CRÉER (préfixe : /api/ecc-attack) :
  POST /api/ecc-attack/bsgs           → Baby-step Giant-step
  POST /api/ecc-attack/pohlig-hellman → Pohlig-Hellman
  POST /api/ecc-attack/anomalous      → Attaque courbes anomales

ATTAQUES ECC À DÉMONTRER :

  1. BABY-STEP GIANT-STEP (BSGS)
     Problème : Résoudre Q = k·G (trouver k)
     Complexité : O(√n) vs O(n) force brute
     Entrée   : Point G, Point Q, ordre n (petit)
     Sortie   : k trouvé + nombre d'étapes + visualisation

  2. POHLIG-HELLMAN
     Contexte : Ordre du groupe n a de petits facteurs premiers
     Entrée   : G, Q, n = p1^e1 * p2^e2 * ...
     Sortie   : k via CRT + facteurs utilisés

  3. COURBES ANOMALES (#E(Fp) = p)
     Contexte : Courbes où le nombre de points = p (le module)
     Attaque  : Smar's attack — transfert vers Fp additif
     Sortie   : k trouvé trivialement

STYLE UI :
  - Couleur accent : #c084fc (violet)
  - Visualisation graphique des étapes BSGS si possible
  - Explication pédagogique de chaque attaque

FORMAT RÉPONSE BACKEND RECOMMANDÉ :
  {
    "success": true,
    "attack_name": "Baby-step Giant-step",
    "result": { "k": 42 },
    "steps": ["Étape 1...", "Étape 2..."],
    "complexity": "O(√n)",
    "explanation": "Explication de la vulnérabilité..."
  }
